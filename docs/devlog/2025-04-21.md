Back in action after a long hiatus!

I've been trying to figure out where to start back in and I've been thinking about two things:

First, the script keeps stopping so that's a great place to start. Where should debugging start? How to avoid this in the future? How to help with debugging?

Second, I realized what I want to do as a first major milestone here: I want to run abstract `SELECT` SQL statements on the entirety of my cloud JSON locally. Which means we need an extra step in the data pipeline before recipes are run: JSON -> SQL. I realized that representing the `JOIN` clauses in recipes is going to cause a lot of duplication.

But, we're starting the first boring one: how to figure out WTF went wrong when things aren't running? Or, first, how do we know if things are going wrong?

In my case, I noticed that my latest Strava activities are not coming down. I looked in the raw JSON folder and saw that the last activity saved was 2024-12-15. OK, now what?

First thing I think of is lets check the logs ... but first reinstall the command since I'm on a newer version of Node (already seeing some troubles here):

```bash
$ npm install -g pdpl-cli
# ... success
$ pdpl api:list
# ... all previously configured APIs are still there
$ pdpl api:logs strava
# ... last run was 2024-12-21 with no errors
```

OK, not too hard. Last time it ran was last year. Maybe that's when I bumped the node version and `pdpl` was not installed? Definitely need a way to install this without NPM ([looks like this isn't too hard](https://medium.com/geekculture/building-a-node-js-cli-with-typescript-packaged-and-distributed-via-homebrew-15ba2fadcb81)). Then, of course, I'd love to convert this to Deno ... but we're getting ahead of ourselves now 😄.

Let's try to run it now:

```bash
$ pdpl api:get strava
```

That got the last 3 activities and a bunch of historic ones, but those are pretty deep in the history, page 7 according to `pdpl api:queue:get strava`. I need to reset the historic queue which I don't think I can do. The queue operations aren't very intuitive and I'm missing some commands I need. Maybe we can add a reset command to rebuild the queue? Or maybe just a `--rebuild` flag for `set`? The latter feels like a better fit for now.

OK, that seemed to do the trick ✨
